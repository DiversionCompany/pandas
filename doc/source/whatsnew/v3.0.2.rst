What's new in 3.0.2 (March XX, 2026)
---------------------------------------

These are the changes in pandas 3.0.2. See :ref:`release` for a full changelog
including other versions of pandas.

{{ header }}

.. ---------------------------------------------------------------------------
.. _whatsnew_302.enhancements:

Enhancements
~~~~~~~~~~~~
- Added support for :func:`pd.col` expressions in :meth:`Series.case_when` (:issue:`64070`).

.. ---------------------------------------------------------------------------
.. _whatsnew_302.regressions:

Fixed regressions
~~~~~~~~~~~~~~~~~
- Fixed bug in :func:`concat` where the order of items affected whether :attr:`DatetimeIndex.freq` was preserved when using ``CustomBusinessDay`` frequency (:issue:`64253`)
- Fixed regression in :meth:`DataFrame.groupby` and :meth:`Series.groupby` where grouping by a timezone-aware datetime column did not preserve the timezone in the result index (:issue:`57192`)
- Fixed regression where creating a :class:`Index` from a big-endian NumPy array (e.g. ``dtype='>f4'``) raised ``ValueError: Big-endian buffer not supported on little-endian compiler`` when accessing index properties like :attr:`Index.is_unique` or :meth:`Index.get_indexer` (:issue:`53234`, :issue:`46085`)
- Fixed regression in :meth:`HDFStore.select` where the ``where`` clause on a datetime index silently returned empty results when the index had non-nanosecond resolution (:issue:`64310`)
- Fixed regression in :meth:`Series.interpolate` where ``limit_direction="both"`` with ``limit`` greater than the Series length raised ``ValueError`` (:issue:`64322`)

.. ---------------------------------------------------------------------------
.. _whatsnew_302.bug_fixes:

Bug fixes
^^^^^^^^^
- Fixed bug in :func:`read_sql_query` where column names appeared in data cells instead of actual values when the DB-API cursor returned rows as dicts (e.g. from a ``row_factory`` that returns dict objects such as those used by pymysql's ``DictCursor``) (:issue:`52437`)
- Fixed bug in :meth:`~pandas.DataFrame.to_json` and :meth:`~pandas.Series.to_json` where null-like values in the index (``None``, ``np.nan``, ``pd.NA``) were serialized using their string representation (e.g. ``"nan"``, ``"None"``, ``"<NA>"``) instead of JSON ``null`` (:issue:`31801`)
- Fixed bug in :meth:`Styler.to_typst` where hidden rows or columns created empty cells ``[]`` in the output and inflated the column count (:issue:`64663`)
- Fixed bug in :meth:`Index.map` and :meth:`Series.map` where passing a :class:`DataFrame` as the mapper raised a confusing ``ValueError: Data must be 1-dimensional`` instead of a clear error message (:issue:`24800`)
- :func:`col` and expressions derived from it failed with power (``**``) and matrix multiplication (``@``) operators (:issue:`64267`)
- Assigning :attr:`pd.NA` to a string column could trigger a PyArrow error and corrupt data (:issue:`64320`)
- Bug when using :func:`col` with Python functions :func:`bool`, :func:`iter`, :func:`copy`, and :func:`deepcopy` either failed or produced incorrect results; these now all raise a ``TypeError`` (:issue:`64267`)
- Fixed bug in the :meth:`~Series.sum` method with python-backed string dtype returning incorrect value for an empty Series and ignoring the ``min_count`` argument (:issue:`64683`)
- Fixed bug in :meth:`DataFrame.sum` crashing on an empty :class:`DataFrame` with both string and numeric columns (:issue:`64657`)
- Fixed bug where :meth:`DataFrame.div` ignored the ``axis`` argument when used with ``level`` for MultiIndex columns (:issue:`64428`)
- Fixed regression in :meth:`DataFrame.var`, :meth:`DataFrame.std`, and :meth:`DataFrame.sem` with ``axis=1`` returning ``object`` dtype instead of ``float64`` when the DataFrame contains mixed numeric dtypes (e.g. ``int``, ``float``, ``bool``) (:issue:`55194`)
- Fixed bug where :meth:`Series.str.contains`, :meth:`Series.str.match`, :meth:`Series.str.fullmatch`, :meth:`Series.str.replace`, and :meth:`Series.str.count` raised ``ArrowInvalid`` when using Python-style Unicode escape sequences (e.g. ``\\uXXXX``) in regular expressions with the PyArrow-backed string dtype (:issue:`63901`)
- Fixed bug where setting values via :meth:`Series.loc` with a partial :class:`MultiIndex` key (e.g. ``ser.loc[0, :]``) produced ``NaN`` values when the right-hand side was a :class:`Series` obtained from the same object (:issue:`46837`)
- Fixed regression where :meth:`Index.astype` with a NumPy string dtype (e.g. ``np.str_``, ``np.dtype("U10")``) raised ``NotImplementedError`` instead of returning an ``object``-dtype :class:`Index` (:issue:`50127`)
- Fixed bug in :meth:`Series.mask` and :meth:`DataFrame.mask` where passing a condition containing ``pd.NA`` or ``np.nan`` (object-dtype condition) raised ``TypeError`` instead of treating ``NA``/``NaN`` as ``False`` (i.e. keeping the original value at those positions) (:issue:`35429`)
- Fixed bug where :meth:`DataFrame.replace` and :meth:`Series.replace` raised ``TypeError`` when replacing arbitrary Python objects (e.g. instances of custom classes) in object-dtype columns (:issue:`36522`)
- Fixed bug in :class:`~pandas.arrays.ArrowExtensionArray` where string concatenation (``+``) with a scalar string or another Arrow string array raised ``TypeError`` when the array used ``pa.large_string()`` dtype due to type mismatch in PyArrow's ``binary_join_element_wise`` (:issue:`64393`)
- Added documentation note that older versions of ``fastparquet`` (before pandas 3.x compatibility updates) may produce incorrect index values when reading parquet files, because pandas 3.x :class:`Index` constructors now copy NumPy arrays by default; upgrading ``fastparquet`` or switching to the ``pyarrow`` engine resolves the issue (:issue:`64298`)
- Fixed bug in :meth:`Series.convert_dtypes` where calling it on a ``StringDtype(storage='pyarrow', na_value=np.nan)`` Series would silently downgrade the storage to ``'python'`` instead of preserving the original backend (:issue:`64239`)
